# 好用程度指标体系

每一轮优化都对照这份指标：先跑评测拿数字，改完再跑，**数字变好才留下改动**。

## 评测工具

| 命令 | 测什么 | 说明 |
|---|---|---|
| `npm run eval:coverage` | 抽取覆盖率（42 个真实网站） | 无头 Chrome 打开 `tools/eval/sites.json` 的站点，对比「用户可见的应翻文本」与抽取器产出，按原因归类漏抽；同时把各站单元落盘到 `.cache/eval/texts/` |
| `npm run eval:cost` | token 放大系数 / 批量构成 | 把上一步的真实网页单元送进真实 `Engine` 离线重放；`--set batchItems=48` 可做参数对比 |
| `DEEPSEEK_API_KEY=… npm run eval:cost -- --real --only wikipedia,mdn` | 真实 token、缓存命中、首条/整页耗时 | 每站最多 400 段，控制花费 |

真实网站会变化、偶尔会被反爬拦截（结果标为「疑似被拦截」，不计入汇总）。比较两次结果以**同一批站点的中位数**为准。

## 指标与目标

### 1. 抽取覆盖率
| 指标 | 定义 | 目标 | 当前 |
|---|---|---|---|
| 正文召回（中位数） | 块级文本 ≥ 40 视觉长度的可见文本被抽成单元的比例 | ≥ 98% | **100%** |
| 正文召回 < 90% 的站点数 | | 0 | **0**（修复前 7） |
| 全文召回（中位数） | 含导航、按钮等全部可见文本 | ≥ 97% | 95.9%（第 1 轮 94.3%） |
| 单次抽取主线程耗时 | `collect()` | ≤ 50 ms | 中位 15 ms / 最大 50 ms（Reddit，影子树较多） |
| 属性文本覆盖 | placeholder / alt / title / aria-label | 待定 | 0（未实现） |

### 2. token 消耗
| 指标 | 定义 | 目标 | 当前（离线估算） |
|---|---|---|---|
| 放大系数 | 输入 token ÷ 去重后原文 token | ≤ 1.3 | **1.48**（合并口径，基线 2.1），中位 1.68 |
| 系统提示词占输入比例 | | ≤ 15% | 34%（基线 45%） |
| 每请求平均段数 | | ≥ 40 | 33（基线 16；短页面段数本身不足） |
| 前缀缓存命中率 | DeepSeek `prompt_cache_hit_tokens` ÷ 输入 | — | 0%：DeepSeek 不缓存 ≤ 280 token 的前缀，此项改为靠「减少请求数」 |
| 重试浪费率 / 失败段数 | 因格式错误 / 超时重发的 token 占比 | ≤ 3% / 0 | 真实 6 站 0 失败（开启思考时 420 段失败） |

### 3. 速度
| 指标 | 目标 | 当前 |
|---|---|---|
| 首屏第一段译文出现 | P50 ≤ 1.5 s | API 首条结果中位 0.95 s（不含页面抽取与渲染） |
| 首屏全部完成 | P50 ≤ 4 s | 需真实模式测 |
| 中等文章整页完成 | ≤ 15 s | 需真实模式测 |

### 4. 翻译质量
格式保真（占位符 / 数字 / 链接）100%；译文对齐 100%；抽样 100 段让强模型评 1–5 分，目标均分 ≥ 4.3；同页术语一致 ≥ 95%。

### 5. 美观与不破坏页面
每页布局破坏数（溢出、遮挡、横向滚动条）为 0；插入译文的布局偏移 CLS ≤ 0.1；还原后 DOM 与翻译前一致 100%；评测集截图人工过目。

### 6. 易用性
安装到翻出第一页 ≤ 3 步；常见错误（密钥错、余额不足、限流）都有一句中文指引。

### 7. 简洁性 / 无感
| 指标 | 定义 | 目标 | 当前 |
|---|---|---|---|
| 触发成本 | 翻译一页所需操作 | 快捷键 1 次；常用站点自动翻译 0 次 | 1 / 0（已支持） |
| 默认可见设置项 | 设置页不展开「高级」时能看到的输入项 | ≤ 8 | **6**（基线 24） |
| 页面打扰 | 正常翻译时出现的弹窗 / 提示；进度提示停留时间 | 0 个弹窗；进度条完成后 ≤ 1.5 s 消失 | 待测 |
| 无效消耗 | 已是中文的页面触发自动翻译时的 API 请求 | 0 | 待测 |
| 页面卡顿 | 插件造成的主线程长任务（> 50 ms） | 0 | 抽取最大 50 ms，渲染待测 |

## 基线记录

### 2026-10-17 第 1 轮：`display:contents` 与 MathJax 误伤
- 根因 1：`display:contents` 的元素没有盒子，`checkVisibility()` / `getClientRects()` 恒为不可见，`isVisible()` 把整棵子树当成隐藏。MDN、Next.js 把整个 `<main>` 包在这种元素里；Reddit、BBC、卫报、Substack、Discord 的卡片也是。
- 根因 2：`SKIP_CLASS_RE` 不区分大小写地匹配 `MathJax`，arXiv 摘要 `<blockquote class="abstract mathjax">` 被整块跳过。
- 正文召回：MDN 1.4% → 92.9%，Next.js 0% → 100%，Reddit 0.8% → 99.2%，BBC 19% → 94.2%，卫报 2.2% → 100%，Discord 38% → 100%，arXiv 36.5% → 100%；没有站点变差。

### 2026-10-17 第 2 轮：token、速度、Shadow DOM、设置页
真实 DeepSeek `deepseek-flash`，6 站（Wikipedia、MDN、Reddit、卫报、GitHub、HN）整页：

| 改动 | 输入 token | 输出 token | 总耗时 | 失败段 |
|---|---|---|---|---|
| 基线（默认开启思考、标签协议、24 段 / 2000 字） | 27,942* | 68,010 | 97 s | 420 |
| 关闭思考（`thinking: disabled`） | 38,529 | 24,284 | 36 s | 0 |
| + 行协议 `N\|text` | 33,928 | 19,389 | 36 s | 0 |
| + 批次 64 段 / 5000 字 | 26,462 | 19,661 | 30 s† | 0 |

\* 基线有 420 段失败没有发出完整请求，输入 token 偏低，不可直接比较。† 该次并发为 6；默认并发保持 4。
合计：**输出 token −71%、总耗时 −63%（默认并发 4 下 97 s → 约 36 s）、失败 420 → 0**；按全部完成的口径，输入 token 再 −31%。

- DeepSeek 官方已只剩 `deepseek-flash` / `deepseek-v4-pro`，`deepseek-chat` 是 flash 的别名，同样默认思考。
- DeepSeek 前缀缓存对 ≤ 280 token 的系统提示词不命中，系统提示词每次全额计费 → 用更大的批次减少请求数。
- Shadow DOM：Trailhead 全文召回 68.3% → 98.8%、正文 90.7% → 100%；GitHub 93% → 98.6%；`shadow-dom` 损失 1.1% → 0.3%。
- 设置页默认可见输入项 24 → 6；新装默认 DeepSeek + `deepseek-flash`，安装后只需「填密钥 → 翻译」两步。

## 剩余漏抽（按损失占比，第 2 轮后）
1. `filtered-other` 1.5%：导航 / 侧栏短链接被过滤（如 dev.to 侧栏 21%）
2. `short-control` 1.1%：按钮短文案按设计不翻（Bluesky 10%、Substack 9%）
3. `iframe` 0.9%：扩展只注入顶层 frame（`allFrames: false`），Cookie 横幅、嵌入内容不翻
4. `shadow-dom` 0.3%：Reddit 头部组件里的少量文字
5. `dialog` 0.1%：原生 `<dialog>` 整块跳过
