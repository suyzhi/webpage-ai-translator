# 好用程度指标体系

每一轮优化都对照这份指标：先跑评测拿数字，改完再跑，**数字变好才留下改动**。

## 评测工具

| 命令 | 测什么 | 说明 |
|---|---|---|
| `npm run eval:coverage` | 抽取覆盖率（42 个真实网站） | 无头 Chrome 打开 `tools/eval/sites.json` 的站点，对比「用户可见的应翻文本」与抽取器产出，按原因归类漏抽；同时把各站单元落盘到 `.cache/eval/texts/` |
| `npm run eval:cost` | token 放大系数 / 批量构成 | 把上一步的真实网页单元送进真实 `Engine` 离线重放；`--set batchItems=48` 可做参数对比 |
| `DEEPSEEK_API_KEY=… npm run eval:cost -- --real --only wikipedia,mdn` | 真实 token、缓存命中、首条/整页耗时、段等待 P50/P90 | 每站最多 400 段，控制花费 |
| `DEEPSEEK_API_KEY=… npm run eval:quality` | 翻译质量 | 12 站按步长抽 220 段经真实 Engine 翻译；自动检查未翻译 / 数字链接丢失 / 协议残留 / 错位嫌疑，再由 `deepseek-v4-pro` 抽 100 段打 1–5 分（一次约 0.02 元） |
| `npm run eval:layout` | 版面与打扰 | 真实加载扩展翻译真实网站首屏（mock 伪中文，长度接近真实译文、无需密钥），检查被截 / 溢出压字 / 被遮挡 / 持续存在的新增横向滚动、撤掉与不可见的译文数、完成提示停留时长；截图存 `.cache/eval/shots/`；`--inspect 文件.js` 可在翻译后的页面里执行调试表达式 |

真实网站会变化、偶尔会被反爬拦截（结果标为「疑似被拦截」，不计入汇总）。比较两次结果以**同一批站点的中位数**为准。

## 基线记录

### 2026-10-17 第 1 轮：`display:contents` 与 MathJax 误伤
- 根因 1：`display:contents` 的元素没有盒子，`checkVisibility()` / `getClientRects()` 恒为不可见，`isVisible()` 把整棵子树当成隐藏。MDN、Next.js 把整个 `<main>` 包在这种元素里；Reddit、BBC、卫报、Substack、Discord 的卡片也是。
- 根因 2：`SKIP_CLASS_RE` 不区分大小写地匹配 `MathJax`，arXiv 摘要 `<blockquote class="abstract mathjax">` 被整块跳过。
- 正文召回：MDN 1.4% → 92.9%，Next.js 0% → 100%，Reddit 0.8% → 99.2%，BBC 19% → 94.2%，卫报 2.2% → 100%，Discord 38% → 100%，arXiv 36.5% → 100%；没有站点变差。

### 2026-10-17 第 2 轮：token、速度、Shadow DOM、设置页
真实 DeepSeek `deepseek-flash`，6 站（Wikipedia、MDN、Reddit、卫报、GitHub、HN）整页：

| 改动 | 输入 token | 输出 token | 总耗时 | 失败段 |
|---|---|---|---|---|
| 基线（默认开启思考、标签协议、24 段 / 2000 字） | 27,942* | 68,010 | 97 s | 420 |
| 关闭思考（`thinking: disabled`） | 38,529 | 24,284 | 36 s | 0 |
| + 行协议 `N\|text` | 33,928 | 19,389 | 36 s | 0 |
| + 批次 64 段 / 5000 字 | 26,462 | 19,661 | 30 s† | 0 |

\* 基线有 420 段失败没有发出完整请求，输入 token 偏低，不可直接比较。† 该次并发为 6；默认并发保持 4。
合计：**输出 token −71%、总耗时 −63%（默认并发 4 下 97 s → 约 36 s）、失败 420 → 0**；按全部完成的口径，输入 token 再 −31%。

- DeepSeek 官方已只剩 `deepseek-flash` / `deepseek-v4-pro`，`deepseek-chat` 是 flash 的别名，同样默认思考。
- DeepSeek 前缀缓存对 ≤ 280 token 的系统提示词不命中，系统提示词每次全额计费 → 用更大的批次减少请求数。
- Shadow DOM：Trailhead 全文召回 68.3% → 98.8%、正文 90.7% → 100%；GitHub 93% → 98.6%；`shadow-dom` 损失 1.1% → 0.3%。
- 设置页默认可见输入项 24 → 6；新装默认 DeepSeek + `deepseek-flash`，安装后只需「填密钥 → 翻译」两步。

### 2026-10-17 第 3 轮：流式、版面、不打扰
- **流式输出**（DeepSeek / OpenAI / OpenRouter）：出现新的一行 `N|` 即确认上一段完成并落地。真实 6 站段等待 P50 4.4 s → 2.6 s（−41%），P90 5.6 s → 4.4 s，首段约 0.6 s；token 不变、0 失败。
- **仅屏幕阅读器可见的文字不再翻译**（`.sr-only`、跳转链接、图标按钮的隐藏标签）：此前会作为可见兄弟节点冒出零散译文（如维基百科 ☰ 下方）；同口径站点送翻单元 −6%。评测基准同步修正（这些字此前被误算为应翻文本）。
- **放不下的译文兜底**：渲染后（入场动画结束后）检查块级译文是否超出定高祖先——被截（overflow 非 visible）或溢出压住后面的内容（visible）——改为行内追加在原文之后；仍放不下则撤掉，不留半截碎片。
- **横向导航条里的短标签一律行内**，与原文不在同一行（被挤到下一行、或被下拉层挤到上方）就撤掉。
- **完成提示**停留 3.2 s → 1.6 s（还原随时可用快捷键 / 弹出面板）。
- 版面评测首屏问题率 11% → **2.4%**（Spiegel 导航 18 → 0、BBC 14 → 1、Microsoft Learn 6 → 0）。

### 2026-10-18 第 4 轮：放不下的译文有去处、Web Components、细节保真
- **限高的长段落预览**（Reddit 信息流摘要、line-clamp 卡片）：译文放到定高容器之后，并截成与原文露出部分相同的行数，不再撤掉。
- **行内译文撑破定高标题**（lit.dev、Discord 文档的 h1/h2）：移到标题之后单独成行；链接、按钮里的撤掉。运行时复查扩展到全部译文。
- **撤掉的译文改挂悬停提示**（`title`）：横向导航条里放不下的短标签（Spiegel、MDN）不占位置，悬停仍可看到；还原时一并摘掉。
- **影子宿主里追加的译文进入同一个具名 slot**：Reddit 帖子摘要的译文此前在 DOM 里但不显示。
- **块之间的短文字（徽章）、行内块里的短标签（下拉按钮）**：译文与原文同一行，不再单独掉到下一行。
- **瀑布流布局**（Microsoft Learn）：译文撑高后出现横向滚动 → 补发 `resize` 让页面自己重排，横向滚动站点 1 → 0。
- **源码换行**：`white-space: normal` 下源码里的换行只是空白，此前被当成真换行，译文凭空多出空行（Reddit 侧栏）。
- **误跳过的正文**：讲解 HTML 标签的段落（标签写在 `<code>` 里）被当成序列化 HTML 丢弃 → MDN 正文召回 94.9% → 98.6%、React 97.3% → 100%、BBC 94.4% → 100%；类名含 `highlight` 片段的正文卡片（Reddit `community-highlight-card`）被当成代码高亮 → Reddit 全文召回 92.8% → 98.9%。
- **自动翻译遇到已是中文的整页**：不请求、不弹提示（手动翻译不受影响）。
- 评测：新增「撤掉」「不可见」译文计数（撤得越多问题率越低，必须一起看）；横向滚动只计提示消失后仍存在的。

### 2026-10-18 第 4 轮（续）：翻译质量
- 新增 `tools/eval-quality.mjs`（见上表）。首次测量均分 4.93、错位 0。
- 低分样本暴露抽取问题：**Sphinx 文档（Python 官方文档等）给每个行内代码加 `notranslate`**，抽取器把它当成「不存在」整段丢掉，送翻的是「the operators , , and can be used」，译文同样缺字。现在句中的 `translate="no"` / `notranslate` 行内片段原样保留在句子里；整块只有这类片段时不送翻。

## 剩余版面问题（第 4 轮后）
1. 整块可点的透明链接层（Reddit、GitHub）、YouTube 播放器广告层盖在译文上：页面本来的设计，不影响阅读，评测仍计入。
2. YouTube 商品货架的定高卡片标题：译文放不下，改为悬停提示。
3. 横向滑动的卡片轨道（MSN、AP News）里个别译文超出轨道可见范围。

## 剩余漏抽（按损失占比，第 2 轮后）
1. `filtered-other` 1.5%：导航 / 侧栏短链接被过滤（如 dev.to 侧栏 21%）
2. `short-control` 1.1%：按钮短文案按设计不翻（Bluesky 10%、Substack 9%）
3. `iframe` 0.9%：扩展只注入顶层 frame（`allFrames: false`），Cookie 横幅、嵌入内容不翻
4. `shadow-dom` 0.3%：Reddit 头部组件里的少量文字
5. `dialog` 0.1%：原生 `<dialog>` 整块跳过
